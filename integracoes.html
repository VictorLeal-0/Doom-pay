Chaves de API

A chave pública é usada no navegador para tokenizar o cartão. A chave secreta fica apenas no seu servidor e nunca deve ser exposta no front-end.

Validação da assinatura

Cada requisição traz um cabeçalho de assinatura que você deve conferir:

X-DoomPay-Signature: sha256=9f2c1b7a3e5d8046ab12cd34ef56ab78
X-DoomPay-Timestamp: 1790000000

Gere o HMAC-SHA256 do corpo da requisição usando sua chave secreta e compare com o valor recebido. Descarte requisições com mais de 5 minutos.

1. Tokenizar o cartão (no navegador, com a chave pública)

POST /v1/tokens
Authorization: Bearer pk_test_4f8a2b9c1d7e3056
Content-Type: application/json

{
  "card": {
    "number": "4111111111111111",
    "holder_name": "ANA R RIBEIRO",
    "exp_month": 9,
    "exp_year": 2029,

  }

{ "token": "tok_1a2b3c4d5e", "brand": "visa", "last4": "4821" }

Códigos de erro

HTTP Código Significado Como resolver
400 invalid_parameter Campo ausente ou mal formatado Confira o corpo da requisição
401 unauthorized Chave inválida ou ambiente errado Verifique o cabeçalho Authorization
402 card_declined Emissor recusou o pagamento Oriente o cliente a tentar outro cartão
404 not_found Transação inexistente Confira o ID informado
409 duplicate_reference Referência já usada Use um identificador único por pedido
422 amount_too_low Valor abaixo do mínimo de R$ 1,00 Ajuste o valor da cobrança
429 rate_limit Mais de 100 requisições por minuto Reduza a frequência e tente de novo
500 internal_error Falha no Doom Pay Repita a requisição em alguns segundos
